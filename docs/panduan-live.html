Panduan E-Portofolio FK UMT · Versi 3

Desain, tema, logo, dan navigasi utama dipertahankan. Versi live menyimpan data di Google Sheets melalui backend Apps Script; halaman demonstrasi terpisah dan hanya memakai data contoh pada peramban.

Untuk admin

  1. Buka proyek Apps Script dari tautan pemasangan yang diberikan tim pengembang. Isi Script Property ADMIN_EMAIL dengan email admin sebenarnya.
  2. Jalankan setupLive. Google meminta persetujuan akses untuk membuat/mengelola basis data. Persetujuan ini dilakukan pemilik akun.
  3. Simpan URL basis data dan kunci ENC_KEY dari Script Properties di tempat institusi yang aman dan terpisah. Jangan unggah kunci atau kata sandi ke GitHub/Drive bersama.
  4. Buat deployment Web app, jalankan sebagai pemilik, akses Anyone. Endpoint menerima permintaan anonim, tetapi semua data pendidikan dilindungi autentikasi dan otorisasi server. Tautan persetujuan pasien memakai token acak.
  5. Untuk Firebase Hosting Spark, tetapkan variabel ELOGBOOK_API_URL ke URL deployment yang berakhir /exec, jalankan node build.js, lalu node scripts/deploy-firebase.js e-portofolio-fk-umt-2026. Hanya folder public yang diterbitkan. Situs resmi: e-portofolio-fk-umt-2026.web.app.
  6. Masuk memakai akun admin awal dari log eksekusi Google dan ganti kata sandi melalui aplikasi. Jangan membagikan log tersebut.
  7. Buat periode, wahana, akun mahasiswa dan pembimbing. Pada menu Penugasan Pembimbing, tentukan mahasiswa, pembimbing, stase, wahana, tanggal mulai/selesai. Peran dosen saja tidak membuka seluruh kohort.

Untuk mahasiswa dan pembimbing

  1. Gunakan kode kasus. Inisial dan nomor rekam medis bersifat opsional; jangan menulis identitas pasien pada kolom bebas.
  2. Catat kasus, refleksi, rencana pengembangan dan target observasi ulang. Tandai kegiatan unggulan promosi/pencegahan/deteksi dini kanker bila relevan.
  3. Minta keputusan pasien melalui tautan persetujuan. Penolakan dan penarikan dicatat; identitas tambahan dibersihkan dan kasus tidak dihitung sebagai capaian valid.
  4. Ajukan kasus ke pembimbing yang ditugaskan. Server memeriksa penugasan dan persetujuan sebelum validasi.
  5. Minta asesmen dengan instrumen yang sesuai. CBD, presentasi kasus, Mini-CEX, DOPS, dan MSF memiliki rubrik berbeda. Rubrik awal harus ditinjau serta disahkan prodi sebelum penggunaan sumatif.
  6. MSF diselesaikan sesudah tiga penilai berbeda yang berwenang memberi penilaian. Ketiganya mengakses asesmen melalui Penilaian.
  7. Keputusan EPA wajib menyertakan bukti asesmen. Level merupakan kategori supervisi; tidak otomatis memberi kewenangan praktik.

Penyimpanan dan laporan

Pastikan indikator “Tersimpan di server” muncul sebelum keluar. Bila koneksi gagal, perubahan tetap berada pada sesi; klik Coba lagi. Jika sesi berakhir, masuk ulang dengan akun yang sama. Konflik ditampilkan untuk ditinjau; aplikasi tidak menimpa data server secara diam-diam. Perubahan yang belum tersimpan tidak dipersistenkan ke perangkat, sehingga menutup peramban dapat menghilangkannya.

Portofolio menampilkan prioritas pengembangan, jumlah bukti dan penilai, kegiatan unggulan, serta nilai sementara. Tombol Cetak / Simpan PDF memakai dialog cetak peramban. Ekspor CSV menghindari identitas tambahan pasien. Pengunduh bertanggung jawab menyimpan laporan institusi secara aman.

Cadangan dan pemulihan

Jalankan backupDatabase secara berkala. Cadangan berupa salinan spreadsheet; periksa aksesnya tetap terbatas. Untuk pemulihan, simpan basis data lama terlebih dahulu lalu ubah Script Property SPREADSHEET_ID ke ID cadangan yang telah diperiksa. Data terenkripsi memerlukan ENC_KEY semula. Uji pemulihan di lingkungan terpisah sebelum dipakai pada layanan utama.

Bantuan
